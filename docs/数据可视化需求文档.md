## 2. 项目背景

基于AI大模型与深度学习的肿瘤辅助诊断系统需要新增数据可视化功能，用于展示检测数据的统计分析结果，帮助管理员直观了解系统使用情况和检测趋势。

## 3. 功能需求

### 3.2 第一行：统计概览

#### 3.2.1 左侧 - 症状检测统计柱状图

**图表类型**：ECharts 柱状图

**数据维度**：
- **X轴（分类）**：症状名称
  - 正常 (normal)
  - 胶质瘤 (glioma)
  - 脑膜瘤 (meningioma)
  - 垂体瘤 (pituitary)
  - 占位性病变 (space_occupying)

- **Y轴（数值）**：各症状类型的检测个数

**数据来源**：
- 从 `detect` 表的 `detection_data` JSON字段解析 `tumor_type` 统计
- 实时计算或定时统计存储到 `dataview_stats` 表

**展示要求**：
- 柱子颜色根据症状类型区分
- 显示数值标签
- 支持hover提示详情

#### 3.2.2 右侧 - 用户预测占比饼图

**图表类型**：ECharts 饼状图 + 详细数值列表

**数据维度**：
- 各用户的预测检测数量占比（百分比）

**饼图下方显示**：
- 用户名称
- 预测个数
- 占比百分比

**数据来源**：
- 从 `detect` 表按 `user_id` 分组统计
- 存储到 `user_prediction_stats` 表

---

### 3.3 第二行：用户分析

#### 3.3.1 左侧 - 用户平均置信度雷达图

**图表类型**：ECharts 雷达图

**数据维度**：
- 不同用户间的平均置信度对比

**展示样式**：
- **百分比数值**：加粗显示（font-weight: bold）
- **用户名**：百分比下方，小两个字号（font-size: smaller）

**数据来源**：
- 从 `detect` 表的 `detection_data` JSON字段解析 `confidence` 计算平均值
- 存储到 `user_confidence_stats` 表

**雷达图指标**：
- 每个用户一个维度
- 数值范围：0% - 100%

#### 3.3.2 右侧 - 实时预测信息表格

**组件类型**：Element Plus Table

**表格列定义**：

| 列名 | 字段 | 说明 |
|------|------|------|
| 用户名 | user_name | 执行检测的用户名称 |
| 权重名称 | model_name | 检测时使用的模型权重文件名 |
| 最小阈值 | conf_threshold | 置信度阈值设置（如0.25） |
| AI助手 | ai_model | 是否使用AI大模型：未使用/DeepSeek/GLM/豆包 |
| 时间戳 | create_time | 检测完成时间 |

**数据来源**：
- `detection_logs` 表 或 `detect` 表关联查询
- 按时间倒序排列，显示最近20条
- 实时刷新（每30秒）或 WebSocket 推送

---

### 3.4 第三行：趋势分析

#### 3.4.1 近十天总预测量波浪曲线图

**图表类型**：ECharts 平滑曲线图（波浪效果）

**数据维度**：
- **X轴**：日期（近10天，格式：MM-DD）
- **Y轴**：当日总预测量个数

**数据来源**：
- `daily_prediction_stats` 表
- 按 `stat_date` 分组统计

**展示要求**：
- 平滑曲线（smooth: true）
- 填充渐变效果
- 显示数据点
- hover显示具体数值

## 4. 数据库设计

### 4.1 数据表汇总

| 表名 | 说明 | 数据来源 |
|------|------|----------|
| `dataview_stats` | 统计数据总表 | 定时任务统计/实时计算 |
| `user_prediction_stats` | 用户预测统计 | detect表聚合 |
| `user_confidence_stats` | 用户置信度统计 | detect表聚合 |
| `daily_prediction_stats` | 日预测量统计 | detect表聚合 |
| `detection_logs` | 实时检测日志 | 检测完成后写入 |

### 4.2 表结构详细设计

#### 4.2.1 dataview_stats 表

```sql
CREATE TABLE IF NOT EXISTS `dataview_stats` (
    `id` INT PRIMARY KEY AUTO_INCREMENT COMMENT '统计ID',
    `stat_type` VARCHAR(50) NOT NULL COMMENT '统计类型: tumor_type/user_prediction/user_confidence/daily',
    `stat_key` VARCHAR(100) NOT NULL COMMENT '统计键（如症状类型名、用户名、日期）',
    `stat_value` DECIMAL(10,4) COMMENT '统计值',
    `stat_count` INT DEFAULT 0 COMMENT '计数',
    `stat_date` DATE COMMENT '统计日期（用于日统计）',
    `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    INDEX `idx_stat_type` (`stat_type`),
    INDEX `idx_stat_date` (`stat_date`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='数据可视化统计表';
```

#### 4.2.2 detection_logs 表（实时日志）

```sql
CREATE TABLE IF NOT EXISTS `detection_logs` (
    `id` INT PRIMARY KEY AUTO_INCREMENT COMMENT '日志ID',
    `detect_id` INT NOT NULL COMMENT '关联的detect表ID',
    `user_id` INT NOT NULL COMMENT '用户ID',
    `user_name` VARCHAR(50) COMMENT '用户名',
    `model_name` VARCHAR(255) COMMENT '使用的权重名称',
    `conf_threshold` DECIMAL(3,2) COMMENT '置信度阈值',
    `ai_model` VARCHAR(50) COMMENT 'AI模型: null/deepseek/glm/doubao',
    `tumor_type` VARCHAR(50) COMMENT '检测出的肿瘤类型',
    `confidence` DECIMAL(5,4) COMMENT '检测置信度',
    `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    INDEX `idx_detect_id` (`detect_id`),
    INDEX `idx_user_id` (`user_id`),
    INDEX `idx_create_time` (`create_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='检测实时日志表';
```

### 4.3 与现有表的关联关系

```
detect 表 (主表)
    │
    ├── detection_data (JSON) ──┬──> tumor_type ────────┐
    │                           ├──> confidence ────────┤
    │                           └──> boxes ─────────────┤
    │                                                   │
    ├── user_id ────────────────────────────────────────┤
    ├── user_name ──────────────────────────────────────┤
    ├── ai_model ───────────────────────────────────────┤
    └── create_time ────────────────────────────────────┘
                                                      │
                                                      ▼
                                              detection_logs 表
```

**关联逻辑**：
- 当检测完成（detect_status = 2）时，从 detect 表解析数据写入 detection_logs
- 定时任务扫描 detect 表更新各统计表

## 5. 接口需求

### 5.1 后端API列表

| 接口路径 | 方法 | 说明 |
|----------|------|------|
| `/dataview/stats/tumorType` | GET | 获取症状类型统计（柱状图数据） |
| `/dataview/stats/userPrediction` | GET | 获取用户预测占比（饼图数据） |

## 6. 非功能需求

### 6.1 性能需求

- 页面首次加载时间 < 3秒
- 图表渲染时间 < 1秒
- 实时日志刷新间隔：30秒
- 统计数据更新：每5分钟或检测完成后触发

### 6.2 兼容性需求

- 支持 Chrome、Firefox、Edge 最新版本
- 响应式布局，支持1280px以上屏幕

### 6.3 安全需求

- 接口需要登录验证
- 只有管理员角色可访问数据可视化页面
