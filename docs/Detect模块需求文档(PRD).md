# Detect.vue 脑肿瘤图像辅助诊断分析模块 - 需求文档 (PRD)

> 适用于 Vibe Coding 开发模式

---

## 1. 产品概述

### 1.1 产品背景
本项目是**基于AI大模型与深度学习的肿瘤辅助诊断系统**，旨在通过深度学习算法自动检测脑肿瘤影像，并结合大模型AI技术为医生提供辅助诊断建议。

### 1.2 产品目标
- 提供友好的Web界面供医生上传和查看脑肿瘤医学影像
- 利用深度学习模型自动检测肿瘤位置和类型
- 借助大模型AI技术生成专业的诊断分析报告
- 保存完整的检测历史记录，支持回溯查看

### 1.3 用户角色
| 角色 | 描述 |
|------|------|
| 医生/诊断师 | 主要使用者，上传影像、查看检测结果、获取AI辅助分析 |
| 系统管理员 | 管理用户、查看系统运行状态 |

## 3. 详细功能需求

### 3.1 影像上传功能

#### 3.1.1 需求描述
用户可以通过点击按钮或拖拽方式上传脑肿瘤医学影像文件。

#### 3.1.2 输入/输出

**输入：**
- 文件格式：JPG、JPEG、PNG、DICOM(.dcm)
- 文件大小：最大 50MB
- 分辨率建议：512x512 或更高

**输出：**
- 上传成功后创建检测记录，返回记录ID
- 页面自动加载显示原图

#### 3.1.3 业务规则
1. 文件格式校验：只允许上传图片格式和DICOM格式
2. 文件大小校验：超过50MB提示错误
3. 自动获取当前登录用户信息，关联到检测记录
4. 上传成功后自动跳转/显示该记录的详情

#### 3.1.4 界面原型
```
┌──────────────────────────────────────────────┐
│  [上传医学影像]  [开始检测]  [AI模型▼] [AI分析] │
└──────────────────────────────────────────────┘
```

---

### 3.2 智能检测功能

#### 3.2.1 需求描述
用户上传影像后，点击"开始检测"按钮，系统调用Python深度学习服务进行肿瘤检测。

#### 3.2.2 输入/输出

**输入：**
- 检测记录ID
- 原始影像路径

**输出：**
- 检测结果图像（带检测框）
- 检测数据JSON：
  ```json
  {
    "tumor_detected": true,
    "tumor_type": "glioma",
    "confidence": 0.94,
    "boxes": [...]
  }
  ```

#### 3.2.3 业务规则
1. 检测状态流转：待检测 → 检测中 → 检测完成/失败
2. 检测过程中按钮显示loading状态，不可重复点击
3. 检测完成后右侧显示结果图，下方显示检测数据概览
4. 检测失败时显示错误信息，允许重新检测

#### 3.2.4 界面原型
```
┌──────────────────────┐  ┌──────────────────────┐
│      原始影像         │  │      检测结果         │
│    ┌──────────┐      │  │    ┌──────────┐      │
│    │          │      │  │    │ ┌──────┐ │      │
│    │   MRI    │      │  │    │ │ 框选 │ │      │
│    │   图像   │      │  │    │ │ 肿瘤 │ │      │
│    │          │      │  │    │ └──────┘ │      │
│    └──────────┘      │  │    └──────────┘      │
│  文件名: brain.jpg   │  │  [状态: 检测完成]     │
└──────────────────────┘  └──────────────────────┘
                          ┌──────────────────────┐
                          │ 肿瘤类型: 胶质瘤      │
                          │ 置信度: 94% ████████ │
                          │ 检测框: 1个           │
                          └──────────────────────┘
```

### 3.3 AI辅助分析功能

#### 3.3.1 需求描述
检测完成后，用户可选择AI大模型，点击"AI辅助分析"按钮，获取专业的诊断分析建议。

#### 3.3.2 输入/输出

**输入：**
- 检测记录ID
- 选择的AI模型（deepseek/glm/doubao）
- 检测数据（作为Prompt的一部分）

**输出：**
- AI生成的分析报告（文本格式）

#### 3.3.3 业务规则
1. 只有在检测完成后才能进行AI分析
2. 分析状态流转：未分析 → 分析中 → 分析完成/失败
3. 支持切换不同模型重新分析
4. 分析报告包含以下章节：
   - 肿瘤类型分析
   - 位置与大小评估
   - 严重程度初步判断
   - 建议后续方案
   - 注意事项

#### 3.3.4 Prompt设计
```
作为一位专业的脑肿瘤影像诊断专家，请根据以下检测结果进行详细分析：

【检测数据】
{detection_data}

请提供：
1. 肿瘤类型分析
2. 位置与大小评估
3. 严重程度初步判断
4. 建议的后续检查或治疗方案
5. 需要注意的事项
```

---

### 3.4 检测历史功能

#### 3.4.1 需求描述
页面下方展示当前用户的检测历史记录列表，支持分页查看和操作。

#### 3.4.2 输入/输出

**输入：**
- 分页参数（pageNum, pageSize）

**输出：**
- 历史记录列表（含检测状态、AI分析状态、创建时间等）

#### 3.4.3 业务规则
1. 按创建时间倒序排列
2. 分页显示，默认每页10条
3. 支持点击查看详情（加载到上方对比区域）
4. 支持删除记录（需二次确认）

## 4. 数据需求

### 4.1 数据库表结构

详见开发文档中的SQL定义，核心字段如下：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT | 主键自增 |
| user_id | INT | 操作用户ID |
| original_image_url | VARCHAR | 原始图像路径 |
| result_image_url | VARCHAR | 结果图像路径 |
| detection_data | JSON | 检测数据（核心） |
| ai_model | VARCHAR | AI模型标识 |
| ai_analysis_result | TEXT | AI分析结果 |
| detect_status | TINYINT | 检测状态 |
| ai_status | TINYINT | AI分析状态 |
| create_time | DATETIME | 创建时间 |

### 4.2 状态定义

**检测状态 (detect_status)：**
- 0: 待检测
- 1: 检测中
- 2: 检测完成
- 3: 检测失败

**AI分析状态 (ai_status)：**
- 0: 未分析
- 1: 分析中
- 2: 分析完成
- 3: 分析失败

## 5. 接口需求

### 5.1 后端API清单

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 图像上传 | POST | /detect/upload | 上传影像并创建记录 |
| 开始检测 | POST | /detect/startDetect/{id} | 调用Python检测 |
| AI分析 | POST | /detect/aiAnalysis/{id} | 调用大模型分析 |
| 分页查询 | GET | /detect/selectPage | 查询历史记录 |
| 查询详情 | GET | /detect/selectById/{id} | 查询单条记录 |
| 删除记录 | DELETE | /detect/delete/{id} | 删除检测记录 |

### 5.2 Python检测服务接口

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 图像检测 | POST | /detect | 接收图像路径，返回检测结果 |

## 6. 非功能需求

### 6.1 性能需求
| 指标 | 要求 |
|------|------|
| 页面加载时间 | < 2秒 |
| 图像上传时间 | < 10秒（50MB） |
| 检测响应时间 | < 30秒 |
| AI分析响应时间 | < 20秒 |
| 历史记录查询 | < 1秒 |

### 6.2 兼容性需求
- 浏览器：Chrome 90+, Firefox 88+, Edge 90+
- 分辨率：最小支持 1366x768

### 6.3 安全需求
1. API密钥存储在服务端，不暴露给前端
2. 文件上传类型和大小限制
3. SQL注入防护（使用MyBatis参数绑定）
4. XSS防护（Vue自动转义）

### 6.4 可用性需求
1. 操作按钮有明确的loading状态提示
2. 错误信息友好提示
3. 支持操作确认（删除等敏感操作）
