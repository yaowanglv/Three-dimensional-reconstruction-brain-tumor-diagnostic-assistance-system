# 批量图像分割 (multi.vue) + 3D可视化 (threedim.vue) 开发方案

> **目标设备**: Jetson Origin Nano Super 8GB  
> **使用场景**: 单人单病例操作（批量分割 → 3D重建）

## Context

蓝鸢尾，本方案旨在为脑肿瘤智能辅助诊断系统新增两个核心功能模块：
1. **multi.vue** - 批量图像分割：用户导入 MRI 切片文件夹，Spring Boot 调度 Python 分割标准化服务，由 Python 直接输出标准格式的 .npy 文件
2. **threedim.vue** - 3D 可视化：加载分割结果，调用 mesh 服务生成 3D 表面模型，前端 Three.js 渲染

当前系统已有 Detect.vue（检测）和 Mask.vue（单张分割），但缺少批量处理和 3D 可视化能力。

```
│  │ 批量分割页面  │    │ 3D可视化页面  │                               │
│  └──────┬───────┘    └──────┬───────┘                               │
│         │                   │                                       │
└─────────┼───────────────────┼───────────────────────────────────────┘
          │                   │
          ▼                   ▼
┌─────────────────────────────────────────────────────────────────────┐
│                  Spring Boot 后端 (localhost:9527)                   │
│  ┌───────────────────┐    ┌───────────────────┐                     │
│  │ MultiController   │    │ MeshController    │                     │
│  │ /multi/*          │    │ /mesh/*           │                     │
│  └────────┬──────────┘    └────────┬──────────┘                     │
│           │                        │                                │
└───────────┼────────────────────────┼────────────────────────────────┘
            │                        │
            ▼                        ▼
┌───────────────────────┐  ┌───────────────────────┐
│ Python 批量分割服务    │  │ Python Mesh 服务       │
│ (端口5001)            │  │ (端口5002)            │
│ segment-batch-api.py  │  │ mesh-api.py           │
│ POST /segment/batch   │  │ POST /mesh/build      │
└───────────────────────┘  └───────────────────────┘
```

**说明**: 两个 Python 服务独立部署，避免资源竞争。批量分割服务使用 GPU 进行 YOLO 推理，Mesh 服务主要使用 CPU 进行 3D 重建。

### 1.2 数据流向（完整链路）

```
用户选择服务器上的 MRI 切片文件夹路径
  │
  ▼
multi.vue 发送路径到后端 POST /multi/startBatch
  │
  ▼
后端验证路径，创建 batch_job 记录，并生成 outputPath
  │
  ▼
后端调用 Python 批量分割服务 POST /segment/batch
  │  传入：jobId、folderPath、outputPath、modelPath、confidence、callbackUrl
  │
  ▼
Python 批量分割服务逐张处理并直接写出：
  ├── images/xxx_slice_001.npy  (原始图片转为 numpy 数组)
  ├── masks/xxx_slice_001.npy   (分割结果转为类别标签数组: 0/1/2/3)
  ├── previews/xxx_slice_001.png (可选，前端预览图)
  └── metadata.json              (切片顺序、标签映射、shape)
  │
  ▼
Python 每处理一张切片回调 Spring Boot /multi/progressCallback
  │
  ▼
multi.vue 显示进度，完成后显示"3D可视化"按钮
  │
  ▼
用户点击"3D可视化"按钮
  │
  ▼
路由跳转到 threedim.vue?casePath=xxx (自动加载)
  │
  ▼
threedim.vue 调用后端 POST /mesh/build
  │
  ▼
后端调用 Python Mesh 服务 POST /mesh/build
  │  输入：case_dir 路径 + 归一化模式（MONAI/轻量级）
  │  处理：重建3D体积 → 强度归一化 → 提取脑组织mesh → 提取肿瘤mesh
  │  输出：{ brain: {vertices, faces}, tumors: {label: {vertices, faces}} }
  │
  ▼
后端返回 mesh JSON 数据给 threedim.vue
  │
  ▼
threedim.vue 使用 Three.js 渲染 3D 表面模型
  - 脑组织：半透明表面
  - 肿瘤标签：彩色实体表面（红/蓝/橙）
  - 交互：透明度滑块、视角切换、自动旋转、缩放
```

## 二、Jetson Origin Nano Super 8GB 兼容性分析

### 2.1 设备规格

| 项目 | 规格 |
|------|------|
| GPU | 1024-core NVIDIA Ampere GPU |
| 显存/内存 | 8GB LPDDR5（共享内存架构） |
| CPU | 6-core Arm Cortex-A78AE |
| AI 性能 | 67 TOPS |
| 功耗 | 7W-25W 可调 |

### 2.2 Python 库兼容性评估

#### ✅ numpy（完全兼容）
- Jetson 官方镜像预装 numpy
- 可通过 `pip install numpy` 安装 ARM64 版本
- **结论**: 无兼容性问题

#### ✅ scipy（兼容，需编译）
- 需要系统依赖: `libopenblas-dev`, `liblapack-dev`
- 安装命令:
  ```bash
  sudo apt-get update
  sudo apt-get install -y libopenblas-dev liblapack-dev
  pip install scipy
  ```
- **结论**: 可安装，首次编译需 5-10 分钟

#### ⚠️ MONAI（需谨慎）
- MONAI 依赖 PyTorch，需要与 Jetson 的 CUDA 版本匹配
- Jetson Origin Nano Super 使用 CUDA 12.x
- **推荐安装方式**:
  ```bash
  # 使用 NVIDIA 提供的 PyTorch wheel
  pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121
  
  # 安装 MONAI（轻量版，不安装可选依赖）
  pip install monai --no-deps
  pip install nibabel pillow
  ```
- **潜在问题**: MONAI 完整版依赖较多，建议只安装核心功能
- **结论**: 可用，但建议提供纯 numpy/scipy 备选方案

#### ✅ Flask + flask-cors（完全兼容）
- 纯 Python 库，无平台依赖
- **结论**: 无兼容性问题

### 2.3 内存使用预估（8GB 设备）

| 阶段 | 内存占用 | 说明 |
|------|----------|------|
| 系统 + 基础服务 | ~1.5GB | Jetson 系统、MySQL、Spring Boot |
| YOLO 分割服务 | ~2-3GB | 模型加载 + 推理 |
| Mesh 重建（MONAI） | ~2-3GB | 3D volume + 归一化 + mesh 提取 |
| Mesh 重建（轻量级） | ~1-2GB | 纯 numpy 归一化，内存更省 |
| **峰值总计** | **~6-7GB** | 8GB 设备可承受，但需顺序执行 |

**关键策略**: 批量分割和 Mesh 生成必须顺序执行，不可并行。

### 3.2.3 Python Mesh 服务

**新建文件**: mesh-api.py

支持两种归一化模式：
- `monai`: 使用 MONAI ScaleIntensityRangePercentiles（1%-99%）
- `lightweight`: 使用纯 numpy 百分位数归一化

```python
def lightweight_scale_intensity(volume: np.ndarray) -> np.ndarray:
    low = np.percentile(volume, 1)
    high = np.percentile(volume, 99)
    volume_clipped = np.clip(volume, low, high)
    vol_min = volume_clipped.min()
    vol_max = volume_clipped.max()
    if vol_max > vol_min:
        scaled = (volume_clipped - vol_min) / (vol_max - vol_min)
    else:
        scaled = np.zeros_like(volume_clipped, dtype=np.float32)
    return scaled.astype(np.float32)
```
