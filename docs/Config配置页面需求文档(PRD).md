## 二、需求背景

### 2.1 问题描述

当前系统在使用过程中存在以下问题：

1. **参数重复配置**：每次使用检测/分割功能时，用户需要重复配置模型路径、阈值等参数
2. **Jetson 端部署适配**：在 Jetson 等边缘设备上部署时，路径、模型、服务地址等配置与 Windows 端不同，需要灵活切换
3. **多模型管理不便**：用户可能有多个模型文件夹（如不同版本、不同精度），但当前只能从后端默认目录加载模型

### 2.2 目标用户

- 主要用户：系统管理员（配置全局参数、模型路径、默认阈值）
- 间接用户：使用脑肿瘤诊断系统的医生/研究人员（使用管理员预设的配置）
- 特殊场景：Jetson 端部署人员

## 三、功能需求

### 3.1 功能概述

新增一个配置页面（Config.vue），集成到 Manager.vue 的"数据管理"子菜单下，**仅管理员可见可操作**。让管理员可以预设默认参数，包括：
- 配置模型文件夹路径（系统自动扫描文件夹下的 .pt/.pth/.onnx 模型文件）
- 配置各页面的默认置信度阈值
- 配置全局服务地址

普通用户在 Detect/Mask/Multi 页面只能从下拉列表选择管理员已配置的模型，不可手动输入模型路径。

### 3.2 功能清单

| 功能编号 | 功能名称 | 优先级 | 说明 |
|----------|----------|--------|------|
| F001 | 模型路径预设 | P0 | 配置模型文件夹路径，自动扫描模型文件，各页面下拉选择 |
| F002 | 默认阈值设置 | P0 | 每个页面可单独设置默认置信度阈值 |
| F003 | 全局服务地址配置 | P1 | 配置后端 API、Python 服务地址 |
| F004 | 配置导入导出 | P2 | 支持配置的导入导出（可选） |

### 3.3 功能详细描述

#### F001 模型路径预设

**需求描述：**
- 管理员在 Config 页面添加模型文件夹路径（如 `D:/models/` 或 `/home/jetson/models/`）
- 后端自动扫描该文件夹下的模型文件（支持 `.pt`、`.pth`、`.onnx` 后缀）
- 扫描结果保存到数据库，前端页面（detect/mask/multi）从数据库读取模型列表
- 每个页面（detect/mask/multi）可独立配置不同的模型文件夹
- 管理员可以"删除"模型记录（仅从数据库删除显示记录，**不删除源文件**）
- 支持重新扫描刷新模型列表

**用户故事：**
> 作为系统管理员，我希望能够预先配置好模型文件夹路径，系统自动扫描其中的模型文件，这样医生在使用检测功能时可以直接从下拉列表选择，而不需要手动输入路径。

**验收标准：**
1. 可以添加/删除模型文件夹路径配置
2. 添加路径后，系统自动扫描该文件夹下的 .pt/.pth/.onnx 文件
3. 扫描结果保存到数据库，包含模型名称、路径、所属页面、文件类型等信息
4. 各页面的模型下拉列表从数据库读取，仅显示已配置的模型
5. 删除模型仅删除数据库记录，不删除物理文件
6. 支持手动触发重新扫描

#### F002 默认阈值设置

**需求描述：**
- 每个页面可单独设置默认置信度阈值
- 阈值范围：**0.05 ~ 0.95**（步长 **0.1**）
- 页面默认值：
  - detect: 0.45
  - mask: 0.45
  - multi: 0.25

**用户故事：**
> 作为系统管理员，我希望能够在配置页面统一设置各功能的默认阈值，这样医生打开页面时自动应用最佳阈值，无需重复调整。

**验收标准：**
1. 可以通过滑块或输入框设置阈值（范围 0.05-0.95，步长 0.1）
2. 保存后，各页面自动应用配置的阈值
3. 阈值变更实时同步到已打开的页面

#### F003 全局服务地址配置

**需求描述：**
- 配置后端 API 地址（默认：http://localhost:9527）
- 配置 Python 检测服务地址（默认：http://localhost:5001）
- 配置 Python 分割服务地址（默认：http://localhost:5001）

**用户故事：**
> 作为 Jetson 端部署人员，我希望能够配置服务地址，这样系统可以连接到不同的后端服务，适配不同的部署环境。

**验收标准：**
1. 可以修改各服务地址
2. 保存后，系统使用新配置的地址
3. 支持地址格式验证

## 四、非功能需求

### 4.1 性能需求

- 配置页面加载时间 < 1 秒
- 模型扫描时间 < 5 秒（针对常规模型文件夹）
- 配置保存/读取操作 < 100 毫秒

### 4.2 兼容性需求

- 支持 Chrome、Firefox、Edge 等主流浏览器
- 支持 Windows 和 Linux（Jetson）操作系统
- 路径格式兼容 Windows（`D:\...`）和 Linux（`/home/...`）

### 4.3 安全性需求

- Config 页面仅管理员角色可见可操作
- 普通用户无法访问配置页面，也无法在 Detect/Mask/Multi 页面手动输入模型路径
- 模型路径验证：确保路径在允许范围内，防止目录遍历攻击

### 4.4 可用性需求

- 界面风格与现有页面保持一致
- 操作简单直观，无需额外学习成本
- 提供重置为默认值的功能
- 模型扫描状态实时反馈（扫描中/完成/失败）

## 五、数据结构设计

### 5.1 数据库表结构

#### 5.1.1 模型配置表 (model_config)

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGINT | 主键，自增 |
| page_type | VARCHAR(20) | 页面类型：detect/mask/multi |
| folder_path | VARCHAR(500) | 模型文件夹路径 |
| model_name | VARCHAR(200) | 模型文件名 |
| model_path | VARCHAR(500) | 模型完整路径 |
| model_type | VARCHAR(10) | 模型类型：pt/pth/onnx |
| is_active | TINYINT | 是否启用：0-禁用 1-启用 |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 更新时间 |

#### 5.1.2 系统配置表 (system_config)

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGINT | 主键，自增 |
| config_key | VARCHAR(50) | 配置键 |
| config_value | VARCHAR(500) | 配置值 |
| description | VARCHAR(200) | 配置说明 |
| updated_at | DATETIME | 更新时间 |

**配置键说明：**
- `threshold.detect`: detect 页面默认阈值
- `threshold.mask`: mask 页面默认阈值
- `threshold.multi`: multi 页面默认阈值
- `global.backend_url`: 后端 API 地址
- `global.python_detect_url`: Python 检测服务地址
- `global.python_segment_url`: Python 分割服务地址

### 5.2 前端配置数据结构

```javascript
// 从后端获取的配置数据结构
{
  // 模型配置
  models: {
    detect: [
      { id: 1, folderPath: 'D:/models/detect', modelName: 'best.pt', modelPath: 'D:/models/detect/best.pt', modelType: 'pt' }
    ],
    mask: [
      { id: 2, folderPath: 'D:/models/mask', modelName: 'best.pth', modelPath: 'D:/models/mask/best.pth', modelType: 'pth' }
    ],
    multi: [
      { id: 3, folderPath: '/home/jetson/models', modelName: 'model.onnx', modelPath: '/home/jetson/models/model.onnx', modelType: 'onnx' }
    ]
  },

  // 默认阈值
  thresholds: {
    detect: 0.45,
    mask: 0.45,
    multi: 0.25
  },

  // 全局设置
  global: {
    backendUrl: 'http://localhost:9527',
    pythonDetectUrl: 'http://localhost:5001',
    pythonSegmentUrl: 'http://localhost:5001'
  }
}
```

## 七、与其他模块的关系

### 7.1 依赖关系

- Config 页面依赖 Manager.vue 的布局框架
- Config 页面依赖 vue-router 进行路由管理
- Config 页面依赖 Element Plus UI 组件库
- Config 页面依赖后端 API 进行配置读写和模型扫描

### 7.2 被依赖关系

- Detect.vue 依赖 Config 的阈值和模型列表
- Mask.vue 依赖 Config 的阈值和模型列表
- Multi.vue 依赖 Config 的阈值和模型列表

### 7.3 权限控制

- Config 页面路由添加 `requiresRole: 'admin'` 权限控制
- Manager.vue 侧边栏菜单仅对管理员显示"系统配置"菜单项
- 普通用户在 Detect/Mask/Multi 页面的模型选择使用 `el-select` 组件，**不允许手动输入**（去掉 `allow-create` 和 `filterable` 的创建功能）

## 八、验收标准

### 8.1 功能验收

1. 仅管理员可见"系统配置"菜单项和页面
2. 管理员能够成功添加模型文件夹路径
3. 系统自动扫描文件夹下的 .pt/.pth/.onnx 文件并保存到数据库
4. 管理员能够"删除"模型记录（仅删除数据库记录，不删除物理文件）
5. 能够成功设置默认阈值（范围 0.05-0.95）
6. 配置保存后，各页面（Detect/Mask/Multi）能够正确读取并应用配置
7. 普通用户在 Detect/Mask/Multi 页面只能从下拉列表选择模型，不能手动输入

### 8.2 性能验收

1. 页面加载时间 < 1 秒
2. 模型扫描时间 < 5 秒（针对常规模型文件夹）
3. 配置保存/读取操作 < 100 毫秒

### 8.3 兼容性验收

1. 在 Chrome 浏览器上正常运行
2. 在 Windows 和 Linux 系统上正常运行
3. 路径格式兼容两种操作系统

## 九、风险与限制

### 9.1 风险

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 模型文件夹路径不存在或无权限 | 扫描失败 | 添加路径验证，提示用户检查路径 |
| 模型文件被物理删除但数据库记录仍在 | 模型无法加载 | 定期清理无效记录，加载时验证文件存在性 |
| 扫描大量模型文件耗时过长 | 用户体验差 | 添加扫描进度提示，支持异步扫描 |

### 9.2 限制

- 仅管理员可以配置系统参数
- 普通用户无法手动输入模型路径，只能从预设列表选择
- 删除模型仅删除数据库记录，不删除物理文件
- 全局服务地址修改需要刷新页面生效
